# ARDOS Guardian G2

Guardian G2 is the private experimental `2.x` line. It shares history with the
public Guardian G1 line through 1.0.0 and then diverges to develop Guardian's
own soundcard payload modem and other field experiments.

| | Guardian G1 | Guardian G2 |
| --- | --- | --- |
| Repository | `bubakbubak500/ARDOS-Guardian` | `bubakbubak500/ARDOS-Guardian-G2` |
| Version line | `1.x` | `2.x` |
| Local branch | `main` | `g2` |
| Remote | `origin` | `g2` |
| Remote branch | `main` | `main` |

VARA remains the default compatible payload transport. G2's modem is
experimental and is selected only when both peers negotiate it. Current
implementation and verification boundaries are in [`STATUS.md`](STATUS.md),
and modem operation is in [`docs/G2_MODEM.md`](docs/G2_MODEM.md).

## Repository boundary

Both product lines use one local clone, so the current branch determines the
product being edited. The configured G2 push refspec maps the local `g2` branch
to `main` in the private repository.

```powershell
git switch g2
git push g2 g2:main

git switch main
git push origin main
```

Never merge or push G2-only modem/companion work into the public G1 repository
without an explicit product decision. Tags are shared locally but must be
pushed to the intended named remote explicitly.

```powershell
git push g2 v2.3.4
git push origin v1.0.1
```

## Product and data separation

G1 and G2 can be installed side by side. They must not run against the same
radio or VARA ports simultaneously.

| | Guardian G1 | Guardian G2 |
| --- | --- | --- |
| Display name | Guardian | Guardian G2 |
| Executable | `Guardian.exe` | `Guardian-G2.exe` |
| Install directory | `%LOCALAPPDATA%\Programs\Guardian` | `%LOCALAPPDATA%\Programs\Guardian-G2` |
| Data directory | `%APPDATA%\Guardian` | `%APPDATA%\Guardian-G2` |
| AppUserModelID | `OK7PS.ARDOSGuardian` | `OK7PS.ARDOSGuardian.G2` |
| Installer | `Guardian-<version>-setup-win-x64.exe` | `Guardian-G2-<version>-setup-win-x64.exe` |

The distinct Inno Setup AppId, executable name, update channel and data
directory are safety requirements. Sharing the profile would allow an older G1
build to discard unknown G2 settings. On its first run only, G2 may copy a G1
configuration into its own directory; it never writes back.

The updater and release manifest must always point to
`ARDOS-Guardian-G2`. A private release may return 404 to an unauthenticated
updater; it must never fall back to the public G1 manifest.

## Build and release

Use the project Python and run the tests with a workspace-owned pytest temp
directory on machines where the system temp directory has mixed ownership.

```powershell
.\.python311\python.exe -m pytest -p no:cacheprovider `
  --basetemp .build-temp\pytest-g2
.\build.ps1
.\build_installer.ps1 `
  -Compiler "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" `
  -ReleaseBaseUrl "https://github.com/bubakbubak500/ARDOS-Guardian-G2/releases/latest/download"
```

Build release artifacts only after the source is committed. Rebuild from that
commit, verify checksums, then tag the exact commit. The complete checklist is
[`docs/RELEASING.md`](docs/RELEASING.md).
